To prevent agents from reverse-engineering Realgoal's source (`~/.pi/agent/git/github.com/stllok/realgoal`) during `/goal` and `/plan` without bloating idle sessions:
1. All 6 tools in `src/tools/register-tools.ts` declare `promptSnippet`; `realgoal_control` also sets `promptGuidelines` forbidding source-code reads. `targetPhase` uses an explicit 16-phase `Type.Union` with description.
2. `before_agent_start` in `src/lifecycle/register-hooks.ts` injects `Legal Next Phases` (via `getLegalNextPhases` from `src/domain/reducer.ts`), `Phase Contract` (`describePhaseContract`), and a pointer to the `realgoal` skill only while a workflow is active.
3. `skills/realgoal/SKILL.md` (exposed via `package.json` `pi.skills: ["./skills"]`) holds on-demand reference rules for `finalized.md` validation, `realgoal_todo` + `realgoal_finish(recordGoalLevelVerification: true)`, static HTML/SVG `realgoal_preview` constraints, and `realgoal_delegate`.

For `/plan` finalization:
1. `advancePhase` (`src/domain/reducer.ts`) allows `discovery | design | analysis -> finalization` before `finalized.md` exists; `finalizedCandidateHash` is only required when advancing into `draft_review` or `publication_choice`.
2. `realgoal_control(action: "finalize")` (`src/tools/register-tools.ts`) registers `finalized.md` and, when entering `publication_choice` with `ctx.hasUI`, immediately presents the 5-option publication menu (`spec`, `plan`, `both`, `refine`, `stop`). When a plan is published, it chains into the execution menu (`direct`, `subagent`, `stop`); `terminate: true` is set only in headless mode (`!ctx.hasUI`).
