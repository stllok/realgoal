`checkWorkerWriteAllowed` (src/services/worker-service.ts) returns false for any path containing `/realgoal/draft/` before it checks the allowed roots. This protects draft state from child workers. Reusing it in the planning `tool_call` guard (src/lifecycle/register-hooks.ts) with `[paths.draftDir]` blocked every write into the draft folder during /plan (e.g. preview HTML for realgoal_preview). The fix is for the planning guard to call `isCandidateInsideRoot(workspaceCwd, paths.draftDir, target)` from src/services/path-safety.ts. Test P01 in test/planning-and-preview.test.ts asserts that draft writes are allowed.
