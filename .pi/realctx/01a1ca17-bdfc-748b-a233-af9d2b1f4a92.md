In `@earendil-works/pi-coding-agent`, `ctx.signal` aliases `agent.signal` (`activeRun.abortController.signal`). When the user aborts a turn (Escape), `ctx.signal.aborted` becomes `true` immediately and **remains `true`** while Pi unwinds the active run and emits `tool_execution_end`, `message_end`, `turn_end`, `agent_before_settle`, and `agent_settled`.

Pitfalls & required pattern in Effect-based Pi extensions (`realgoal`):
1. `ManagedRuntime.runPromise(effect, { signal })` squashes fiber interruptions into `Error("All fibers interrupted without error")` even when `effect` uses `Effect.orElseSucceed` / `Effect.match` (which only catch typed `Fail` errors, not `Interrupt`). Always bridge Effect to Pi Promises with `runPromiseExit` and handle `Cause.hasInterruptsOnly(exit.cause)` gracefully while still rejecting non-interrupt `Die` defects.
2. Do not pass `ctx.signal` to post-abort bookkeeping hooks (`session_start`, `tool_execution_end`, `message_end`, `agent_before_settle`), or an already-aborted `ctx.signal` will interrupt state bookkeeping before it runs.
